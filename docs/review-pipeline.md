# 审查流水线：五层、配比、顺序与成本

这份文档回答一个问题：**这个仓库的「复核」由哪几层组成，各自何时参与，代价多少，以及它不做什么。**

它不引入新的产品承诺：`signoff` 的判定仍然只有退出码，仍然零运行时依赖、默认离线。
外部模型评审（下称 L3）永远在证据链之外——它产出的是**候选断言**，不是结论。

## 1. 五层，各自只回答一个问题

| 层 | 形态 | 唯一能回答的问题 | 不能回答 |
| --- | --- | --- | --- |
| L0 静态 | `node --check`、lint、`tsc`、semgrep | 语法/类型/模式级错误存在吗 | 行为对不对 |
| L1 断言（唯一记分层） | 自检用例（当前 630 条） | 我**想到的**行为还成立吗 | 我没想到的行为 |
| L2 反证 | 反向对照（NC）、变异测试 | 这些断言**能不能**红 | 断言覆盖了需求吗 |
| L3 独立评审 | 云端模型 / 审计子代理 / 本地模型 | 我**没想到**什么 | 确定性判断（会飘） |
| L4 环境矩阵 | CI 多点 | 换个 OS/Node 还行不行 | 逻辑对错 |
| L5 人类 | 你 | 发不发 | 细节正确性 |

判据：一层审查只有在「能说不」「可复算」「不与其它层共盲区」三条同时成立时才有价值。

**记分规则：只有 L1、L2 记分。L3 只产出候选断言，不产出结论；L4 只证明环境可复现；L5 只有否决权。**
层级混用——让 L4 的绿去替 L1 说话——就是「看起来审过了」的来源。

## 2. 配比：按改动面分配

| 改动面 | L0 | L1 | L2 | L3 | L4 | L5 |
| --- | --- | --- | --- | --- | --- | --- |
| 文档/文案 | 否 | p5 | 否 | 不参与 | push | 发布 |
| 纯测试 | 是 | 必跑 | 必跑 | 30% | push | 发布 |
| 单文件逻辑 | 是 | 必跑 | 触及测试时 | 30% | push | 发布 |
| 跨文件契约/重构 | 是 | 必跑 | 是 | 必参与 | push | 发布 |
| 闸门语义/退出码/安全/发布脚本 | 是 | 必跑 | 是 | 必参与 + 双人 | push | 必须 |
| 依赖/构建 | 是 | 必跑 | 是 | 必参与 | push | 发布 |

换算成每次迭代的参与概率：L1 与 L4 每次都在；L2 约一半（改到测试时才跑）；**L3 约 20–30%**；L5 只在发布时。

L3 的边际价值在「断言写得出来」的地方最低，在「断言写不出来」的地方最高。全量上 L3 是浪费，高风险面不上 L3 就要等发布时才撞上。

**没参与的层必须打印 `skip` 与原因**（`signoff guard` 已实现）：配比本身不是问题，静默降级才是。

## 3. 顺序：四条不能换的理由

```text
写实现 → 冻结 diff → L0 静态 → L3 独立评审 → 意见断言化 → L2 反证 → L1 全套 → push（L4）→ L5 验收
```

| 若把顺序换掉 | 后果 |
| --- | --- |
| 先 L4 再 L3 | CI 只是重复本地；评审意见来得太晚，没有时间断言化 |
| 先断言化再 L3 | 锚定：评审会照着已有断言看，看不见断言之外的东西 |
| L3 之后还改 diff | 审的和推的不是同一份（`signoff review --verify` 就是为这件事存在的） |
| 断言化后不做 L2 | 得到一条永远绿的断言，比没有更糟 |

## 4. 质量与时间的影响（估算，含假设）

估算基于本机实测：每步上下文 98.8k tokens、缓存命中 94.7%、一次迭代约 45 步、diff 62–231 行。

| 变更 | 质量影响 | 时间影响 |
| --- | --- | --- |
| 加 L3（仅高风险面） | 增强：本轮审计的 13 条发现**全部**落在高风险面（`lib/guard.js`、`lib/p2.js`、`lib/release.js`、`action.yml`、版本快照） | 评审调用 15–30 s；人读意见 1–3 min（只在 20–30% 的迭代发生） |
| L3 只喂 diff、不喂整个仓库 | **可能下降**：上下文变少，跨文件缺陷更难看出。未实测，需要回放集对照 | 省 16 倍输入 token |
| 合并独立只读调用（45 步 → 25 步） | 不变：合并的只是互不依赖的只读调用，闸门命令不合并 | 省约 44% 模型时间 |
| diff 体积上限 400 行 | 增强（业界经验值，本仓库未实测） | 多一次拆分，约 +2 min/次 |
| 变异测试 | 增强：能量化断言是否真的有效 | 本地 15–30 min，可与其它工作并行 |

诚实结论：**质量不会因为「分层参与」而下降**，因为参与与否是可见的；会下降的是「L3 只给 diff」这一条，代价是省 16 倍 token，需要用自己的回放集测过再决定是否保留。

## 5. 成本模型

单价假设：V4.1-Flash 为 0.05 / 0.20 每百万 token（输入/输出），缓存命中按 1/10 计；前沿模型按 3 / 15 计（美元）。这些是标价假设，不是账单。

| 项 | 每次迭代 | 备注 |
| --- | --- | --- |
| 基线：实现循环 45 步 × 98.8k | **约 0.27**（缓存不打折则约 1.6） | 人民币，主要成本在这里 |
| L3 云端 diff 评审（1 次） | 0.002（Flash）/ 0.15（前沿） | 3k 入 / 0.8k 出 |
| L3 审计子代理（每 5 次 1 次） | 0.006（Flash）/ 0.39（前沿） | 10k 入 / 1.6k 出 |
| L3 本地模型（1 次） | 0.02–0.27 | 电费 + 硬件折旧 |
| L2 变异测试（本地） | 0 | 只有时间 |
| L4 私有仓库 CI 加一档 | 0.72 | 公开仓库为 0 |

两种配比的合计：

| 组合 | 每次迭代 | 相对基线 |
| --- | --- | --- |
| 便宜组合：本地模型常驻 + 云端只审高风险 + 审计每 5 次 | 0.31–1.65 | 约 +10% |
| 前沿组合：每次前沿评审 + 每 5 次前沿审计 | 0.82–2.14 | +33% 到 +190% |

要压成本，杠杆从大到小：**砍步数**（45 → 25 省约 44%）、**保住缓存**（命中从 94.7% 掉到 80% 约 ×3）、只喂 diff（16×）、分层触发、先跑 L0 淘汰低级问题、限制评审输出长度、把已断言化的意见进回放库。

## 6. 它不做什么

- 不把模型放进 `signoff`，不改变任何闸门的退出码；
- 不允许 L3 的「通过」替代任何一条断言；
- 不在默认路径上联网；
- 不承诺检出率：审查基准里最好的模型在植缺陷任务上的 F1 也只有 32.3 量级，L3 是补充，不是判据。
