# 用本机模型审代码，再把这一步钉进 signoff

`signoff review` 不含模型，也不评代码：它只把「谁在什么时候看过哪份 diff」写成存证，并在
`--verify` 时回答一个问题——**现在要推出去的这份 diff，是不是刚才被审过的那一份**。所以「用哪个
模型审」是你自己的选择，工具不替你选，也不假装替你选。本文给出一个可复算的接法。

## 它证明什么、不证明什么

| 证明了 | 没证明 |
| --- | --- |
| 评审记录绑定到 diff 的 sha256 短哈希，改一个字节就失效 | 这次评审的质量 |
| 存在覆盖当前 diff 的 `approve` 时 `--verify` 退 0，否则退 1 | `--by` / `--model` 说的是真的（是自述） |
| 存证落在仓库根 `.signoff/reviews.jsonl`，换目录也看得见 | 评审人真的读过代码 |

任何工具的「我审过了」都只是自述。signoff 换不来真话，它只保证**审过的那份和发出去的那份是同一份**。

## 三步

1. 起一个能回答的模型（任意 OpenAI 兼容端点都行，不一定要 Ollama）：

```bash
ollama pull qwen2.5-coder:7b
ollama serve        # 默认 127.0.0.1:11434
```

2. 让审查工具产出意见（`ocr` 只是一种；没有它就用你的 agent 或编辑器看 diff）：

```bash
ocr config set provider ollama-local
ocr review          # 读 git diff 出意见，这一步不产生 signoff 存证
```

3. 人看过意见之后，把这一步记下来：

```bash
signoff review --by "me" --model "ollama-local/qwen2.5-coder:7b" --note "7B 报 2 处未使用变量，人工确认其余无碍"
signoff review --verify     # 0 = 当前 diff 有 approve；1 = 没有
```

## 让它成为推送前的一关（可选，默认关闭）

在 `.signoff/config.json` 里加一行：

```json
{
  "review_on_push": true
}
```

之后 `git push` 会在闸门全过之后再问一次：

- 仓库里还没有任何存证 → 打印原因并跳过（不拿这个吓唬刚装上的仓库）；
- 有存证但当前 diff 没有被 approve → 红，并告诉你上次被批准的是哪个哈希。

默认关闭的原因很实在：这个开关一旦打开，**每次改动都需要重新审一次**（评审绑定哈希，不是绑定仓库）。
那是使用者的决定，不该是工具的默认动作。

## 多个模型怎么分工（一个能复算的做法）

1. 常驻的小模型（7B 一类）扫格式、未使用变量、明显的空引用、测试里被注释掉的断言；
2. 它抓到的问题**必须落成一条会红的用例**才算数——`test/selftest.js` 里加一条断言；
3. 判不了的架构问题留给人，不要让它替人签收。

换 14B 或 32B 只改变第 1 步的命中率，第 2、3 步不变。这就是「模型是加速器，不是保证」的具体含义。

## 三条红线不变

`--no-verify`、`SIGNOFF_SKIP=1`、调阈值让红变绿——这三条不在任何模式下放开，`review_on_push` 也不开。
