## 二、已经证过的三条结论

1. **绑定 ≠ 质量保证。** 一次 review 只覆盖它看到的那版 diff；新改动让绑定失效，这一点由自检钉住
   （「pre-push: a changed diff invalidates the approval」）。
2. **判定只认退出码。** 0 通过 / 1 红 / 2 用法错误；报告页、建议器、趋势都改不了判定。
3. **测量工具必须被测量。** 这条被自己的工具咬了两次：
   第一次自检夹具把结果写进仓库真实历史，第二次把 91 个点的基线覆盖成 3 个点。
   两次都是「工具说没事」，也都靠人看数字发现的。现在有 `--history` / `--out` 隔离，
   但**没有断言能保证「自检以后不会再写仓库记录」**——这本身就是阶段 3 的一个待办。

## 三、剩余存活点：11 条，决定不再销

最近一次统计：**87.5%（77/88）**——`lib/cov.js` 45 个活点全部转红，`lib/p2.js` 32/43。
剩下 11 条**全部**在 `lib/p2.js` 的排序与文本格式化路径上：

| 行 | 变异 | 被改的是 |
| --- | --- | --- |
| `:57` | `true->false` | `isScenario()` 把空场景目录判成有的场景 |
| `:87` | `ne->eq` | `nameCmp` 的比较方向 |
| `:95` | `true->false` | `TextDecoder` 的 `fatal`（坏 UTF-8 是否要抛） |
| `:150` | `or->and` | 场景数据「不是对象」的三重判断 |
| `:161` | `eq->ne` | Windows 上按小写比较扩展名 |
| `:169` | `and->or` | 升级到 scenario 级的两个前提 |
| `:175` | `or->and` | 报告里 `app` 名的回落 |
| `:185` | `or->and` | 报告里检查项的拼接 |
| `:232` | `or->and` | 下一个参数是不是负数（`--min -1`） |
| `:238` | `eq->ne` | 参数按 int 还是字符串解析 |
| `:265` | `eq->ne` | 报告里筛选 scenario 级应用 |

**为什么停在这里**：这 11 条不改变任何一次判定的通过与否——它们改变的是报告的**措辞、顺序、字段名**。
销掉它们需要为每一处写一条「字符串长什么样」的断言，那是把测试变成格式化输出的镜像：
以后改一个字就要改测试，而判定错没错仍然不知道。投入产出比已经为负。

**留档而非留白**：这份清单本身就是产物。它们不是「没测到」，是「测了，且知道它们只影响可读性」。
真正该担心的是另两个文件：`lib/report.js`（报告页）、
`lib/i18n.js`（多语言）——它们**一个变异点都没建**。`bin/signoff.js` 已建成基线：
67 个点 49 杀（73.1%），见 [`verify/mutate/baseline-bin-2026-11-17.md`](../verify/mutate/baseline-bin-2026-11-17.md)。

三条实测结论（留档，免得下次又「怀疑等价」）：

- `cov --base` / `--file` 不带值是**可杀**的：变异版把 `undefined` 收成字符串 `"undefined"` 继续跑，退出码从 2 变 0。
- diff 模式下「覆盖率里有本次没动过的文件」是**可杀**的：变异版对 `undefined` 取 `.size` 直接抛异常。
- `cov:200` 的 cwd 回落确实等价：非 git 目录下两种实现的 stdout/stderr/退出码/写出的 `cov.json` 逐字节相同。

关于 `lib/cov.js` 的 45/45：它只说明这 45 个变异点都会让自检变红，不等于这个文件没缺陷。

清单原件：[`verify/mutate/baseline-2026-11-16.md`](../verify/mutate/baseline-2026-11-16.md)。

## 五、明确不做的事

1. **不把变异测试塞进 pre-commit**：单点 55 s，而 guard 现在 2.6 s；塞进去就是逼人 `--no-verify`，
   等于自己拆掉唯一的硬边界。
2. **不让 `signoff risk` 参与判定**：建议器一旦能否决，它就得自己先被证明可信，那是循环论证。
3. **不每次都跑全量变异**：按风险排序抽样（默认 30 点）是常态，全量是季度基线。
4. **不在没有「发布 x.x.x」口令时发布**。
