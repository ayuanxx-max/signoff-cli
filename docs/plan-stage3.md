## 二、已经证过的三条结论

1. **绑定 ≠ 质量保证。** 一次 review 只覆盖它看到的那版 diff；新改动让绑定失效，这一点由自检钉住
   （「pre-push: a changed diff invalidates the approval」）。
2. **判定只认退出码。** 0 通过 / 1 红 / 2 用法错误；报告页、建议器、趋势都改不了判定。
3. **测量工具必须被测量。** 这条被自己的工具咬了两次：
   第一次自检夹具把结果写进仓库真实历史，第二次把 91 个点的基线覆盖成 3 个点。
   两次都是「工具说没事」，也都靠人看数字发现的。现在有 `--history` / `--out` 隔离，
   但**没有断言能保证「自检以后不会再写仓库记录」**——这本身就是阶段 3 的一个待办。

## 四、阶段 3 的四个目标与验收判据

每个目标都写成「能判红」的形式，否则不算完成。

### 目标 1：把 `lib/cov.js` 从 47.9% 提到 70% 以上

- 验收：`node tools/mutate.js --files lib/cov.js --cmd "node test/run-all.js"` 全量跑完，被杀死比例 ≥ 70%；
- 且新增断言里至少 3 条属于「解析类」（diff / lcov / 跳过通路），不是格式化分支；
- 预算：`lib/cov.js` 48 个点 × 55 s ≈ 45 分钟，可分两个 worktree 并行。

### 目标 2：自检不得写仓库真实测量记录（用断言钉住）

- 现状：靠 `--history` / `--out` 人工隔离，没有任何断言防止以后有人再加一条写入；
- 验收：新增一条自检——跑完 suite 前后对 `.signoff/mutants.json` 与 `mutants-history.jsonl` 取哈希，
  必须不变；先写失败版（改回默认路径会红），再改实现。

### 目标 3：拿到真实的逃逸数据（替代推测）

- 现状：`verify/replay/defects.json` 只有 4 条历史缺陷；「20 轮内逃逸 ≤ 1」是预测，不是结论；
- 验收：连续 20 次迭代记录 `review → 合并 → 事后发现的缺陷`，写进 `.signoff/escapes.jsonl`；
  报告页的「逃逸缺陷」从回放集切到这份记录（或两者分开列，数字必须能追溯）。

### 目标 4：用真实数据校准风险权重

- 现状：`gate-module +3`、`measurement-surface +4`、`weak-measured-score +2` 等权重，只有方向验证，
  没有「分数高 → 后来真的出问题」的对照；
- 验收：目标 3 的数据攒到 ≥20 条后，做一次「风险分位 vs 逃逸率」对照表；某条权重若与该表矛盾就改掉，
  改完在 `docs/review-pipeline.md` 记一行「哪次数据让它变的」。

## 五、明确不做的事

1. **不把变异测试塞进 pre-commit**：单点 55 s，而 guard 现在 2.6 s；塞进去就是逼人 `--no-verify`，
   等于自己拆掉唯一的硬边界。
2. **不让 `signoff risk` 参与判定**：建议器一旦能否决，它就得自己先被证明可信，那是循环论证。
3. **不每次都跑全量变异**：按风险排序抽样（默认 30 点）是常态，全量是季度基线。
4. **不在没有「发布 x.x.x」口令时发布**。

## 六、已知不确定（写在这里，免得下次当成结论）

1. **51.6% 只覆盖两个文件**：`bin/signoff.js`、`lib/report.js`、`lib/i18n.js` 未测，
   不能说「本仓库变异分 51.6%」。
2. **样本小**：A0 的 8 点窗、A3 的 5 点单跑都是小样本；趋势里已经按 `分数% (N)` 标注样本量，
   不要把 8 点的 87.5% 与 91 点的 51.6% 放在一起比较。
3. **等价变异靠人判断**：`verify/mutate/ignore.json` 每条都有理由与实测记录，但「等价」本身可错；
   发现判错的要移出并在清单里注明。
4. **A3 之后没有重测**：39 条是「44 − 5」，新加的断言可能顺带杀死别的不在清单里的点，
   真实数字要等下一次全量跑。
