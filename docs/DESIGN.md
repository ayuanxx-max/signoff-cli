# DESIGN.md — 界面规则（能被检查的那部分）

SignOff 的界面只有两处：单文件看板（`signoff report --html`）与 DSH 侧栏面板。改 UI 前读这一页；
改完用 `node tools/ui-shot.js` 出图，自己看一眼再提交。

## 1. 数字必须带词

- 行内每个数字都要有「词 + 值」：金额写 `费用 $0.02`（英文 `cost $0.02`），token 写 `46.00M tok`，
  次数写 `39,486 次调用`，比率写 `过闸率 100%`。
- 禁止裸 `$0.02`；`$` 紧贴数字，但它前面必须有一个词，`$` 不与 `·` 相邻。
- 分隔符 `·` 两侧各一个空格；同一行里词与值之间用空格，不用斜杠。
- 读不到的量写 `—`，不写 `0`：0 是"确实是零"，`—` 是"没读到"，两者不能混。

## 2. 间距与字号

- 间距只用 4 的倍数（4 / 8 / 12 / 16 / 24）；13px、11.5px 这类历史值只许出现在已有的 meta 文本里，不新增。
- 字号阶：11.5（只给 meta 小字）、12、13、14、18、22。
- 正文行高 1.45–1.6；卡片之间留 16，卡片内边距 12。

## 3. 颜色

- 状态只用三色：红 `#f87171` 未过、黄 `#fbbf24` 待测、绿 `#4ade80` 全过；三色只表达状态，不做装饰。
- 正文与次要文字各一档灰（`--muted`），不新造第四档灰。
- 图表里的同一条线在一张页面里保持同一颜色，不随机上色。

## 4. 文案

- 判定说「哪几项没过」，不说「可以发 / 不能发」：判定权在人手里。
- 金额是估算：写「按 DeepSeek 官方价估算」，不把它写成账单；闸门本身不消耗 token，页面要能看出这一点。
- 面板只读：不出现通过、跳过、放宽的控件。

## 5. 怎么检查

`npm test` 里的 UI 断言（会红的那种）：

- `class="cost"` 元素的可见文本必须形如 `费用 $…` / `cost $…`；
- 看板必须能离线打开：没有 `src=`、`href=` 外链，没有 `fetch`/`XHR`（C3）；
- 面板任务行的 meta 必须带 `M.cost` 标签再跟金额。

提交前自问三句：

1. 这一行里每个数字都有词吗，会不会被读成别的单位？
2. 空值写的是 `—` 还是 `0`？
3. 少一行会不会更清楚？删掉之后信息还在不在？
